# npm Optional Dependency Behavior (Phase 0 Validation)

Tested on **2026-11-26** on Windows 11 (`win32-x64`) with:
- Node.js: `v24.13.0`
- npm: `11.11.0`

## Summary

In npm `11.11.0`, fresh `npm install` of packages with platform-specific optional dependencies (`esbuild`, `rollup`) **did** record all 27 platform variants in `package-lock.json` (`lockfileVersion: 3`), and re-running `npm install` with `node_modules` present preserved all 27 entries.

However, **the underlying CI failure mode still exists** whenever a lockfile is incomplete (for example: lockfiles generated by older npm versions affected by `npm/cli#4828` / `npm/cli#8320`, lockfiles generated with `--no-optional` / `--omit=optional`, or lockfiles edited/merged manually):
- `npm ci` on another platform fails with `EUSAGE` (`Missing: <pkg>@<version> from lock file`), OR
- `npm ci` silently skips optional binaries if the parent package falls back or does not declare the missing entry in a way that triggers `EUSAGE`.

Additionally, `npm ci --dry-run --ignore-scripts --os=<os> --cpu=<cpu> --libc=<libc>` is supported in npm `11.11.0`, which enables `lockmatrix --verify-with-npm` to cross-check static findings against npm itself.

## Recorded Experiments

### Experiment 1: Fresh `npm install esbuild` on `win32-x64`
- Command: `npm init -y && npm install esbuild --no-audit --no-fund`
- Result: `package-lock.json` (`lockfileVersion: 3`) contained **27** `esbuild` entries (`node_modules/esbuild` plus 26 `@esbuild/*` platform packages including `linux-x64`, `darwin-arm64`, `win32-x64`, `linux-arm64`, etc.).

### Experiment 2: Re-install with `node_modules` present (after deleting `package-lock.json`)
- Command: `Remove-Item package-lock.json && npm install --no-audit --no-fund`
- Result: `package-lock.json` still contained **27** `esbuild` entries. npm `11.11.0` did not prune other platforms' optional dependencies in this single-package test.

### Experiment 3: `npm ci --dry-run --ignore-scripts --os=linux --cpu=x64 --libc=glibc` on complete `esbuild` lockfile
- Command: `npm ci --dry-run --ignore-scripts --os=linux --cpu=x64 --libc=glibc`
- Result (exit code `0`):
  ```text
  add @esbuild/linux-x64 0.28.2
  remove @esbuild/win32-x64 0.28.2

  added 1 package, and removed 1 package in 1s
  ```

### Experiment 4: `npm install rollup` + pruned `package-lock.json`
- Fresh `npm install rollup --no-audit --no-fund` produced **27** `rollup` entries in `package-lock.json`.
- After removing `node_modules/@rollup/rollup-linux-x64-gnu` from `package-lock.json` and running:
  `npm ci --dry-run --ignore-scripts --os=linux --cpu=x64 --libc=glibc`
- Result (exit code `1`):
  ```text
  npm error code EUSAGE
  npm error
  npm error `npm ci` can only install packages when your package.json and package-lock.json or npm-shrinkwrap.json are in sync. Please update your lock file with `npm install` before continuing.
  npm error
  npm error Missing: @rollup/rollup-linux-x64-gnu@4.68.8 from lock file
  ```

## Why `lockmatrix` Is Still Needed

1. **Instant, offline static check**: `npm ci --dry-run` requires network/cache access and must be invoked once per target platform. `lockmatrix` checks all target platforms (`linux-x64-glibc`, `linux-x64-musl`, `linux-arm64-glibc`, `win32-x64`, `darwin-arm64`, `darwin-x64`, etc.) in milliseconds from `package-lock.json` alone.
2. **Legacy & mixed-tooling lockfiles**: Teams still encounter lockfiles generated on older npm releases, `--omit=optional` runs, or bad merge conflict resolutions.
3. **Clear matrix visibility**: `lockmatrix` produces a per-package, per-platform coverage matrix and SARIF/GitHub annotations suitable for PR checks.
